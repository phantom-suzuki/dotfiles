# AI コーディングエージェント運用の用語

Claude Code や Codex を動かす場面は、日本語の定訳が固まっていない語が多い。
そのため Claude は標準語を知らないまま、日本語の比喩を作って説明しがちである。
この表は、その比喩を作らずに済むだけの標準語をそろえる。

## セッションとコンテキスト

| 用語 | 意味 | ユーザーへの言い方 | 注意 |
|---|---|---|---|
| セッション | Claude Code を 1 回起動してから終えるまでの、1 本の会話と作業のまとまり | 1 回分の会話のまとまり | 並列で動かす 1 本も 1 セッションと数える |
| ターン | ユーザーの 1 発言に対して Claude が応答を返し終えるまでの単位 | 1 往復のやりとり | ツールを何回呼んでも 1 ターンに収まる |
| プロンプト | Claude に送る指示文そのもの | Claude に渡す指示の文 | 送った内容全体を指す語ではない |
| システムプロンプト | セッション開始時に自動で読み込まれる、Claude の振る舞いを決める指示 | Claude が最初から持っている前提の指示 | ユーザーの画面には表示されない |
| コンテキストウィンドウ | 1 回のリクエストで Claude が同時に読める文字量の上限 | Claude が一度に覚えていられる量の上限 | 日本語に訳さず、片仮名のまま書く |
| トークン | モデルが文章を扱うときの最小単位で、課金と上限の数え方の基準になる | 文章の量を測るときの単位 | 日本語 1 文字が 1 トークンとは限らない |
| 入力トークン | Claude に送った内容の量 | Claude に読ませた分の量 | 会話が続くほど毎回増える |
| 出力トークン | Claude が生成した内容の量で、思考の分も含む | Claude が書いた分の量 | 思考が長いと出力側が増える |
| コンパクション | 会話が上限に近づいたとき、それまでの経過を要約して続きを進める処理 | 会話が長くなったとき、これまでを要約して続ける仕組み | 公式の日本語訳は無く片仮名で書く |
| 自動コンパクション | コンテキストが設定のしきい値まで埋まると自動で走るコンパクション | 上限が近づくと自動で要約が走ること | `/autocompact` でしきい値を変えられる |
| 起動時コンテキスト | セッション開始時に自動で読み込まれる、指示ファイルと環境情報のまとまり | 会話を始めた時点ですでに読み込まれている情報 | コンパクションの後も読み直される |
| 会話記録（transcript） | セッション中のやりとりをそのまま保存したファイル | やりとりをそのまま残した記録 | 要約後も元の記録は残る |
| セッションの再開（resume） | 保存された会話記録を読み直して、前回の続きから作業を始めること | 前回の続きから始めること | `--continue` は直前の 1 本を指す |
| セッションの分岐（fork） | 既存の会話をそのまま複製し、別の流れとして続けること | 同じ会話を複製して別方向に進めること | 元のセッションには何も起きない |
| 巻き戻し（rewind） | 会話とファイルの状態を、過去のある時点まで戻すこと | やりとりとファイルを前の状態に戻すこと | `/rewind` で実行する |
| チェックポイント | 巻き戻しの戻り先として記録された、会話とファイルの状態 | 戻れる地点として残っている状態 | 手で作る操作ではなく自動で記録される |
| 引き継ぎ | 現在の到達点を文書に残し、別のセッションが続きを進められるようにすること | 次の担当が続けられるよう、今の状況を書き残すこと | 要約と違い、次に何をするかまで書く |
| 自動メモリ | Claude が自分の判断でセッションをまたいで書き残す、学習した事実のファイル | Claude が自分で覚えておくために書くメモ | ユーザーが書く CLAUDE.md とは別物 |
| セッション間メッセージ | 自分が動かしている別のセッションへ、Claude が発見を伝える仕組み | 別々に動かしている会話の間で情報を渡す仕組み | 相手の承認の代わりにはならない |
| コンテキストの逼迫 | 会話が長くなり、上限までの残りが少なくなった状態 | 覚えていられる量の残りが少ない状態 | `/context` で内訳を確認できる |

## 委譲と並列実行

| 用語 | 意味 | ユーザーへの言い方 | 注意 |
|---|---|---|---|
| サブエージェント | 呼び出し元とは別のコンテキストで動き、結果だけを返す補助の Claude | 別の場所で動いて結果だけ返してくる補助役 | 公式表記は subagent の 1 語である |
| 委譲 | ある作業をサブエージェントやチームメイトに渡して進めさせること | 作業を別の担当に渡すこと | 渡した側は結果の要約しか受け取らない |
| 統括セッション | 全体の進め方を決め、委譲先の結果をまとめる側のセッション | 全体をまとめる側のセッション | 公式訳は無い。比喩で呼び換えない |
| 担当セッション | 統括セッションから作業を受け取って、その分だけを進めるセッション | 受け持ちの作業を進める側のセッション | 公式訳は無い。比喩で呼び換えない |
| エージェントチーム | 複数の Claude Code セッションが、共有のタスク一覧と相互連絡で協調する仕組み | 複数の Claude が連絡を取り合って進める仕組み | 既定では無効で、環境変数で有効にする |
| チームリード（team lead） | エージェントチームで、チームメイトを起動し作業を割り当てる側のセッション | 割り振りとまとめを担当するセッション | 1 セッションにつき 1 つで、交代できない |
| チームメイト（teammate） | エージェントチームで、独立したコンテキストを持って作業を進める側のセッション | 受け持ち分を独立して進める相手 | サブエージェントと違い直接会話できる |
| 起動（spawn） | 統括セッションがサブエージェントやチームメイトを新たに動かし始めること | 補助役を新しく動かし始めること | 起動時に渡す指示文が相手の前提になる |
| 並列実行 | 複数の作業を同時に走らせて、全体の所要時間を縮めること | 複数の作業を同時に進めること | 同じファイルを触る作業には向かない |
| 逐次実行 | 前の作業が終わってから次を始める進め方 | 1 つずつ順番に進めること | 依存関係があるときはこちらを選ぶ |
| 同時実行数 | 同じ時点で走らせる並列作業の本数 | いくつを同時に動かすか | 増やすほどトークン消費が比例して増える |
| 一斉委譲（fan-out） | 同じ種類の作業を複数の担当へ一度に配ること | 同じ作業を複数に一度に配ること | 公式訳は無く英語表記のまま使う |
| 集約 | 委譲先から返った結果を 1 つにまとめ、矛盾を解消すること | 返ってきた結果を 1 つにまとめること | 統括セッション側の仕事である |
| 共有タスク一覧 | チームの全員が読み書きする、作業項目とその状態の一覧 | 全員が見ている作業の一覧 | 状態は未着手・作業中・完了の 3 つ |
| タスクの引き取り | 手が空いた担当が、未着手で依存の解けた作業を自分から取ること | 空いた担当が次の作業を自分で取ること | 同時に取らないよう排他制御が働く |
| worktree（作業ツリー） | 同じリポジトリの履歴を共有しつつ、別のディレクトリと別のブランチを持つ作業場所 | 同じリポジトリを別の場所に展開した作業用のコピー | 並列作業でファイルの衝突を避ける手段 |
| 作業ディレクトリの分離 | 並列で動く各セッションに別々の作業場所を与え、編集が干渉しないようにすること | それぞれ別の場所で作業させて、ぶつからないようにすること | worktree がこれを実現する標準手段 |
| 分離（isolation） | サブエージェントを専用の worktree で動かし、主の作業場所に触らせない設定 | 補助役を別の場所に閉じ込めて動かす設定 | frontmatter の `isolation: worktree` で指定する |
| バックグラウンド実行 | 呼び出し元の応答を止めずに、裏で走らせ続けること | 裏で走らせたまま先へ進むこと | 終了時に通知が届く |

## Claude Code の構成要素

| 用語 | 意味 | ユーザーへの言い方 | 注意 |
|---|---|---|---|
| CLAUDE.md | Claude が毎回のセッション開始時に読む、プロジェクトや個人の指示を書いた Markdown | 毎回読ませたい決まりごとを書いておくファイル | 200 行以内に収めると守られやすい |
| ルールファイル | `.claude/rules/` に置き、話題ごとに分けて書いた指示の Markdown | 決まりごとを話題別に分けて置くファイル | CLAUDE.md と同じ優先度で読まれる |
| パス限定ルール | frontmatter の `paths` で対象ファイルを絞り、該当ファイルを読んだときだけ読み込まれるルール | 特定のファイルを触るときだけ効く決まりごと | コンパクション後は再読み込みされない |
| スキル | 手順や参照資料をまとめ、必要になった時点でだけ読み込まれる指示のまとまり | 必要になったときだけ読ませる手順書 | 公式の分類名は Agent Skills である |
| SKILL.md | スキルの本体で、frontmatter と手順の本文からなる Markdown | スキルの中身を書くファイル | 500 行以内に抑え、詳細は別ファイルへ移す |
| Progressive disclosure | 概要だけを常時読ませ、詳細は必要になった時点で読ませる設計 | まず概要だけ読ませ、詳しい話は後から読ませる作り | 定訳が無いため英語表記のまま使う |
| スラッシュコマンド | `/` で始まる名前を打って、スキルや組み込み機能を直接呼び出す操作 | `/` で始まる名前を打って呼び出す操作 | プラグインのものは `プラグイン名:名前` になる |
| hook（フック） | Claude Code の動作の決まった時点で自動実行される、ユーザー定義のコマンド | 決まったタイミングで自動で走らせる処理 | 指示と違い、Claude の判断に左右されない |
| PreToolUse | ツールを実行する直前に走り、その実行を止められる hook | ツールを使う直前に走らせる処理 | 危険な操作を機械的に止める用途に使う |
| PostToolUse | ツールの実行が成功した直後に走る hook | ツールを使い終えた直後に走らせる処理 | 失敗時は PostToolUseFailure が走る |
| UserPromptSubmit | ユーザーが指示を送信し、Claude が処理を始める前に走る hook | 指示を送った直後に走らせる処理 | 指示の内容を書き換えられる |
| SessionStart | セッションを開始または再開したときに走る hook | 会話を始めたときに走らせる処理 | コンパクション直後にも走らせられる |
| Stop | Claude が応答を終えた時点で走る hook | Claude が答え終わったときに走らせる処理 | 終了音の通知などに使う |
| SubagentStop | サブエージェントが作業を終えた時点で走る hook | 補助役が終わったときに走らせる処理 | 起動時は SubagentStart が走る |
| PreCompact | コンパクションが始まる直前に走る hook | 要約が始まる直前に走らせる処理 | 直後に走るのは PostCompact である |
| PermissionRequest | ツールの実行に許可の判断が必要になった時点で走る hook | 許可を求める場面で走らせる処理 | 判断そのものを自動化できる |
| MCP（Model Context Protocol） | 外部のツールやデータ源を AI に接続するための、公開された標準規格 | 外部のツールやデータを Claude につなぐための共通の決まり | 規格の名前で、製品の名前ではない |
| MCP サーバー | MCP に従って、自分の持つツールやデータを Claude に提供するプログラム | 外部のツールを Claude から使えるようにする仲介役 | 入れすぎるとコンテキストを圧迫する |
| スコープ | 設定をどこまでの範囲に効かせるかの区分で、local・project・user の 3 つがある | その設定をどこまでの範囲に効かせるかの区分 | project スコープだけがリポジトリで共有される |
| プラグイン | スキル・エージェント・hook・MCP 設定をひとまとめにして配布できる形式 | 拡張機能をひとまとめにして配れる形式 | 中のスキル名には名前空間が付く |
| マーケットプレース | プラグインの一覧を公開し、導入元として登録できるリポジトリ | プラグインを探して入れてくる先 | 公式と community の 2 つが用意されている |
| 権限モード | そのセッションで Claude が確認なしに実行できる範囲を決める設定 | どこまで確認なしでやらせるかの設定 | Shift+Tab で切り替える |
| Manual モード | ファイル編集・コマンド実行・ネットワーク接続の前に必ず確認を求めるモード | 危ないことは全部聞いてから進めるモード | 設定値は `default` である |
| acceptEdits モード | 読み取りとファイル編集を確認なしで通すモード | ファイルの書き換えまでは黙って進めるモード | ネットワーク接続は確認を求める |
| plan モード | 読み取りだけを許し、計画の承認を得るまで変更を禁じるモード | まず調べて計画を出させ、承認してから進めるモード | 承認するとそのまま実装へ移る |
| auto モード | 別のモデルが操作の安全性を判定し、確認の回数を減らすモード | 安全かどうかを機械が判定して、聞く回数を減らすモード | 判定役のモデルを classifier と呼ぶ |
| dontAsk モード | あらかじめ許可したツールだけを動かし、それ以外は実行しないモード | 許可したものだけ動かし、他は一切やらないモード | CI や自動実行で使う |
| bypassPermissions モード | すべての確認を飛ばして実行するモード | 確認を一切せずに実行するモード | コンテナや仮想マシンの中だけで使う |
| 許可ルール（allow） | 指定したツールや操作を、確認なしで実行してよいと定める設定 | これは聞かずにやってよい、と書いておく設定 | bypassPermissions では効かない |
| 拒否ルール（deny） | 指定したツールや操作を、どのモードでも実行させないと定める設定 | これは絶対にやらせない、と書いておく設定 | すべてのモードで効く |
| 確認ルール（ask） | 指定した操作で必ず確認を求めると定める設定 | これは毎回必ず聞かせる、と書いておく設定 | どのモードでも自動承認されない |
| 設定ファイルの優先順位 | 同じ項目が複数のファイルにあるとき、どれを採用するかの順序 | 同じ設定が重なったとき、どれが勝つかの順序 | 管理設定が最優先で、個人設定が最後 |
| 管理設定（managed settings） | 組織が配布し、利用者の設定では上書きできない設定 | 会社側が決めていて、個人では変えられない設定 | 拒否ルールの徹底に使う |
| 保護パス | どのモードでも自動承認されない、書き込み先として保護されたパス | 何があっても勝手に書き換えさせない場所 | bypassPermissions だけが例外である |

## モデルと推論

| 用語 | 意味 | ユーザーへの言い方 | 注意 |
|---|---|---|---|
| モデル | 入力から応答を生成する言語モデルそのもので、能力と価格が世代ごとに異なる | 応答を作っている本体で、世代ごとに賢さと値段が違う | 名前ではなくモデル ID で指定する |
| モデル ID | API へ渡す、モデルを一意に決める文字列 | どのモデルかを指定するための正式な名前 | 別名は解釈されない場合がある |
| effort（推論の深さ） | 応答 1 回に費やすトークン量を 5 水準で指定する設定で、`low` から `max` まである | どれだけ考え込ませるかの設定 | 定訳が無く、英語表記のまま使う |
| adaptive thinking | 考えるかどうかと考える量を、モデル自身が要求ごとに決める方式 | 考える量をモデル自身に決めさせる方式 | 新しい世代はこちらしか対応しない |
| extended thinking | 思考に使うトークン数を `budget_tokens` で固定して指定する方式 | 考える量を数値で固定して指定する方式 | 4.7 以降のモデルは受け付けない |
| 思考ブロック | 応答を書き出す前に、モデルが内部で考えた内容を収めた部分 | 答える前に考えた内容が入る場所 | 出力トークンとして課金される |
| 温度（temperature） | 次の語を選ぶときのばらつきの大きさを決める設定 | 答えのばらつき具合を決める設定 | thinking を使う場面では指定できない |
| max_tokens | その応答で生成できる出力トークン数の上限 | 1 回の答えで書ける量の上限 | 思考の分もこの上限に含まれる |
| 知識の切れ目（knowledge cutoff） | モデルの学習データが対象としている最後の時点 | モデルが知っている情報の最終時点 | それ以降は検索で補う必要がある |
| 幻覚（hallucination） | 事実と異なる内容や、与えた資料にない内容をモデルが生成する現象 | 事実でないことをもっともらしく書いてしまうこと | 引用や検索で裏を取ると減らせる |
| プロンプトキャッシュ | 同じ前半部分の処理結果を保存し、次の要求で再利用して費用と待ち時間を減らす仕組み | 前回と同じ部分を覚えておいて、処理をやり直さない仕組み | 前半が 1 文字でも変わると効かない |
| キャッシュの書き込み | 新しい内容をキャッシュに保存する処理で、通常の入力より割高になる | 覚え直しにあたる処理で、その分だけ高くつく | 5 分保持で入力の 1.25 倍かかる |
| キャッシュの読み出し | 保存済みの内容を再利用する処理で、通常の入力より大幅に安い | 覚えていた分を使い回す処理で、その分だけ安くなる | 入力の 1 割ほどの費用で済む |
| キャッシュの有効期間（TTL） | 保存した内容が再利用できる時間の長さ | 覚えておいてくれる時間の長さ | 既定は 5 分で、契約により 1 時間になる |
| キャッシュの失効 | 前半部分の変更や時間切れで、保存内容が使えなくなること | 覚えていた内容が使えなくなること | ツール定義の変更でも起きる |
| ツール使用（tool use） | モデルが用意された道具を呼び出し、その結果を受け取って続きを判断すること | Claude が道具を使って、結果を見てから次を決めること | 呼び出しと結果で 2 回の往復になる |

## 作業の進め方

| 用語 | 意味 | ユーザーへの言い方 | 注意 |
|---|---|---|---|
| 実施回 | 同じ手順を繰り返すとき、その 1 回分を指す単位 | 何回目の実施かを数える単位 | 「第 1 回」「第 2 回」と数字で書く |
| 工程 | 作業全体を目的で区切ったときの、ひとまとまりの区切り | 作業を目的ごとに区切ったひとかたまり | 手順の 1 行を指す語ではない |
| 作業時間帯 | その作業に着手してよいと決めた、開始と終了の時刻の範囲 | いつからいつまで作業してよいかの時間 | 「いつまで」を必ず日時で書く |
| 着手条件 | その作業を始めてよいと判断するために、事前に満たすべき条件 | 始めてよいと言える条件 | 満たさないまま着手すると差し戻しになる |
| 完了条件 | その作業が終わったと判断するために、満たすべき条件 | 終わったと言える条件 | 検証できる形で書く |
| 差し戻し | 完了条件を満たしていない成果を、担当へ返して直させること | 条件を満たしていないので、やり直してもらうこと | 何が足りないかを必ず添える |
| 再実行 | 同じ手順を最初からもう一度動かすこと | もう一度、初めからやり直すこと | 途中再開とは区別する |
| 途中再開 | 前回が止まった地点から、残りの手順だけを進めること | 止まったところから続きだけをやること | 再開できる地点を決めておく必要がある |
| 冪等な手順 | 同じ操作を何度実行しても結果が変わらない手順 | 何回やっても同じ結果になる手順 | 再実行しても安全、と言い換えると伝わる |
| ドライラン | 実際の変更を加えずに、何が起きるかだけを出力させる実行 | 本当に変えずに、何が起きるかだけ見ること | Terraform の plan がこれにあたる |
| 依存関係 | ある作業が、別の作業の完了を前提としている関係 | この作業が終わらないと次に進めない、という関係 | 並列化できるかの判断材料になる |
| ブロック | 依存関係が解けておらず、着手できない状態 | 前の作業待ちで手が付けられない状態 | 何を待っているかを明示する |
| 割り当て | どの作業を誰が担当するかを決めること | 誰が何をやるかを決めること | 決めた内容は共有タスク一覧に書く |
| 分担 | 全体の作業を、担当どうしで重ならないように分けること | 重ならないように作業を分けること | 同じファイルを触る分け方は避ける |
| 中断 | 進行中の作業を、完了前に意図的に止めること | 途中でわざと止めること | 止めた地点と理由を記録する |
| 打ち切り | その作業を完了させずに終わりにすると決めること | やらないと決めて終わりにすること | 中断と違い、再開を前提にしない |

## 失敗と対処

| 用語 | 意味 | ユーザーへの言い方 | 注意 |
|---|---|---|---|
| レート制限 | 一定時間あたりの要求数やトークン数に上限を設ける制御 | 短時間に使いすぎると、しばらく止められる制御 | 待てば回復し、失敗ではない |
| 使用量の上限 | 契約ごとに決まった、一定期間に使えるトークン量の上限 | 契約の範囲で使える量の上限 | 5 時間ごとと 1 週間ごとの 2 種類がある |
| 使用量のリセット | 上限に達した使用量が、次の期間の開始とともに戻ること | 使える量が次の期間で元に戻ること | 戻る時刻はエラー文に表示される |
| タイムアウト | 応答が決めた時間内に返らず、処理を打ち切ること | 決めた時間を過ぎたので処理をやめること | 待ち時間を延ばせる場合がある |
| ツール呼び出しの失敗 | Claude が呼び出した道具が、結果を返せずにエラーで終わること | Claude が使った道具が失敗して結果が返らないこと | Claude はエラー内容を読んで次を決める |
| 権限の拒否 | 許可の仕組みが、その操作の実行を認めなかったこと | やってよいかの判断で、実行が認められなかったこと | 同じ操作をそのまま再試行しない |
| 承認待ち | 実行の可否をユーザーに尋ね、返答があるまで止まっている状態 | ユーザーの返事を待って止まっている状態 | 別の担当が代わりに承認はできない |
| 再試行 | 失敗した操作を、条件を変えずにもう一度実行すること | 同じことをもう一度試すこと | 3 回を目安に打ち切る |
| 無限ループ | 同じ操作と同じ失敗を繰り返し、先へ進まなくなる状態 | 同じことを繰り返して先に進まなくなる状態 | 回数の上限を決めて抜ける |
| 暴走 | 指示の範囲を超えた操作を、確認を経ずに続けてしまうこと | 頼んでいないことまで勝手に進めてしまうこと | 拒否ルールと権限モードで防ぐ |
| ガードレール | 危険な操作を機械的に止めるために、あらかじめ用意した制限 | 危ないことを機械的に止める仕組み | 指示文より確実に効く |
| サンドボックス | コマンドの実行範囲をファイルとネットワークの面で制限する隔離環境 | 触れる範囲を制限した中で動かす仕組み | 隔離であり、許可の判断とは別物 |
| プロンプトインジェクション | 読み込んだ文書やツール結果に指示を埋め込み、AI の動作を乗っ取る攻撃 | 読ませた文章に指示を紛れ込ませて操ろうとする攻撃 | 外部から来た文章は指示として扱わない |
| 監査ログ | 誰がいつ何を実行したかを、後から検証できる形で残した記録 | 後から検証できるように残した実行の記録 | 会話記録とは目的が異なる |
| デバッグログ | 不具合の原因を追うために、内部の動作を詳細に記録した出力 | 原因を追うために内部の動きを細かく残した記録 | `--debug` を付けて出力する |
