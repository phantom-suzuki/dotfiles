# インフラ・クラウド・運用の用語

インフラの話は目に見えない仕組みが多く、Claude は日本語の比喩を作りやすい。
特に state / drift / caller / 可観測性 / SLO のあたりで説明が曖昧になりやすい。
AWS の用語は AWS 日本語ドキュメントの表記に合わせ、勝手なカタカナ語や訳語を作らない。

## Infrastructure as Code

| 用語 | 意味 | ユーザーへの言い方 | 注意 |
|---|---|---|---|
| Infrastructure as Code（IaC） | サーバやネットワークの構成をコードで書き、ツールに実物を作らせる方式 | インフラの構成をコードに書いて、その通りに作らせるやり方 | 略称 IaC を初出で開く。構成管理と呼ばない |
| 宣言的（declarative） | 手順ではなく「最終的にどうなっていてほしいか」を書く記述方式 | 完成した状態を書けば、そこへ持っていってくれる書き方 | Terraform はこちら。命令的と対で使う |
| 命令的（imperative） | 目的の状態に至る手順を順番に書く記述方式 | やることを順番に並べて書くやり方 | シェルスクリプトが代表例 |
| state（ステート） | Terraform が管理対象の実リソースと設定内のリソースを対応づけて記録したファイル | Terraform が「今どれを管理しているか」を覚えている記録 | 「状態ファイル」と訳さず state で通す |
| backend（バックエンド） | state をどこに保存し、どうロックするかを決める設定 | state をどこに置くかの設定 | Web のバックエンドと同音異義。文脈を添える |
| plan | 設定と現状を突き合わせ、何を作り・変え・消すかを実行前に一覧で出す操作 | 実際に変える前に、変更内容を一覧で見せる操作 | 必ず読んでから apply する |
| apply | plan で決まった変更を実際のクラウド環境へ反映する操作 | 変更を本当に反映する操作 | 途中で失敗すると部分的に反映される |
| drift（ドリフト） | コードの記述と実際のクラウド上の設定がずれている状態 | コードに書いた内容と、実物の設定が食い違っている状態 | 手動変更が主な原因。「差分」とだけ言わない |
| refresh | 実リソースの現状を読み直して state を最新に合わせる処理 | 実物を見に行って、記録を今の姿に合わせる処理 | plan の前に自動で走る |
| import | すでに存在するリソースを Terraform の管理下に取り込む操作 | 手で作ったものを、あとから Terraform の管理に入れる操作 | 設定コードは自動生成されない。先に書く |
| moved ブロック | リソースの記述上の名前を変えたとき、state 上の対応も付け替える宣言 | 名前を変えても作り直さずに済ませる書き方 | 書かないと削除と新規作成になる |
| removed ブロック | 設定から消すリソースを、実物は残したまま管理下から外す宣言 | コードから外しても実物は消さない、と伝える書き方 | 実物も消したいときは使わない |
| リソースアドレス | `aws_ecs_service.api` のように設定内のリソースを一意に指す文字列 | 設定の中でその 1 つを名指しするための書き方 | ARN（AWS 側の ID）と混同しない |
| module（Terraform モジュール） | 複数のリソース定義をまとめ、値を差し替えて何度も使える再利用単位 | 何度も使い回せる設定のひな形 | 呼ばれる側がモジュール。呼ぶ側は下の caller |
| caller（呼び出し側の設定） | モジュールの参照先と環境ごとの値を書いた `terragrunt.hcl` を置いたディレクトリ | 環境ごとの値を書いて、共通のひな形を呼び出すフォルダ | Terragrunt 公式の呼び名は unit。社内語なので説明を添える |
| unit（Terragrunt のユニット） | `terragrunt.hcl` が 1 つ置かれ、固有の state を 1 つ持つディレクトリ | state を 1 つ持つ、設定の最小のまとまり | 公式用語。社内の「caller」とほぼ同じ対象を指す |
| provider（プロバイダ） | 特定のサービスの API を Terraform から操作できるようにする拡張 | AWS や MySQL を操作するための差し込み部品 | MySQL は `petoju/mysql` を使う（`hashicorp/` は非推奨） |
| lock file（`.terraform.lock.hcl`） | 使用する provider のバージョンとチェックサムを固定する記録ファイル | 使う部品のバージョンを固定しておくファイル | caller 側は commit する。module 側は不要 |
| state lock（ステートロック） | 同時実行で state が壊れないよう、実行中は他の実行を待たせる仕組み | 同時に 2 人が実行して記録が壊れるのを防ぐ仕組み | 異常終了でロックが残る。force-unlock は慎重に |
| init | provider やモジュールを取得し、backend の接続を初期化する操作 | 実行の準備を整える最初の操作 | caller でのみ実行する。module では実行しない |
| dependency ブロック | 別の unit の output を受け取り、実行順序も決める Terragrunt の宣言 | 別の設定が出した値を受け取って、順番も決める書き方 | 値は使わず順序だけ決めるなら dependencies |
| `_envcommon` | 全環境で共通の設定を 1 か所にまとめた Terragrunt のディレクトリ | 全環境で同じ設定を 1 か所に置いておく場所 | 環境ごとの上書きは `env/service/` 側に書く |
| 0-diff | plan を実行しても変更が 1 件も出ない状態 | 実行しても何も変わらない、つまり整合が取れた状態 | 復旧作業の完了条件としてよく使う |

## AWS の主要サービスと概念

| 用語 | 意味 | ユーザーへの言い方 | 注意 |
|---|---|---|---|
| リージョン | AWS のデータセンター群が置かれた地理的な地域の単位 | どの地域の設備を使うかの単位 | リージョンをまたぐ通信は遅く、費用もかかる |
| アベイラビリティーゾーン（AZ） | 1 つのリージョン内で電源と設備が独立した拠点の単位 | 同じ地域の中で、設備が分かれた置き場所 | 複数 AZ に置くと片方が落ちても続く |
| VPC | AWS 上に作る、自分専用の閉じたネットワーク空間 | 自分のためだけに区切られたネットワーク | 作成後に CIDR は縮小できない |
| サブネット | VPC の中を AZ 単位で区切った、より小さな IP アドレスの範囲 | ネットワークを置き場所ごとに区切った小分け | 1 つのサブネットは 1 つの AZ にしか属せない |
| セキュリティグループ | リソース単位で受信と送信の通信を許可するルールの集まり | どの通信を通すかを決める、サーバごとの通信許可リスト | 拒否ルールは書けない。許可だけを並べる |
| ネットワーク ACL | サブネット単位で通信を許可・拒否するルールの集まり | ネットワークの区画ごとに通信を許可・拒否する設定 | 戻りの通信も明示が要る。セキュリティグループとは別物 |
| Application Load Balancer（ALB） | HTTP のリクエスト内容を見て振り分ける負荷分散サービス | URL の中身を見て、どのサーバへ送るかを決める装置 | パス単位の振り分けが要るならこちら |
| Network Load Balancer（NLB） | TCP 接続単位で高速に振り分ける負荷分散サービス | 中身を見ずに、接続先を高速に振り分ける装置 | 固定 IP が要るときに選ぶ |
| ターゲットグループ | ロードバランサーが通信を送る宛先をまとめ、健全性を判定する単位 | 振り分け先のサーバをまとめた一覧 | ヘルスチェックの設定はここに書く |
| リスナー | ロードバランサーが待ち受けるポートとプロトコルの設定 | どの番号の入り口で通信を待つかの設定 | 証明書はここに紐づく |
| ECS クラスター | ECS のタスクやサービスを動かす計算資源のまとまり | コンテナを動かす計算資源のまとまり | AWS 日本語表記は「クラスター」 |
| タスク定義 | 使うイメージ・CPU・メモリ・環境変数を書いたコンテナ実行の設計書 | どのコンテナをどんな設定で動かすかの設計書 | 変更のたびに版が増える。版を指定して動かす |
| タスク | タスク定義をもとに実際に起動したコンテナの実行単位 | 実際に動いているコンテナ 1 つ分 | 定義と実体を混同しない |
| ECS サービス | 指定した数のタスクを維持し、落ちたら自動で入れ替える仕組み | 決めた数だけ常に動かし続ける仕組み | バッチ処理には使わない |
| Fargate | サーバの管理なしでコンテナを動かす ECS の実行環境 | サーバを用意せずにコンテナを動かす方式 | EC2 起動タイプより単価は高い |
| Lambda | コードを登録しておき、呼び出しのたびに実行するサービス | 呼ばれたときだけコードを動かす仕組み | 実行時間と同時実行数に上限がある |
| EventBridge | AWS 内外の出来事を受け取り、条件に合う宛先へ転送するサービス | 出来事を受け取って、必要な処理へつなぐ仕組み | 定期実行だけなら Scheduler を選ぶ |
| EventBridge Scheduler | cron やレート式で指定した時刻に、対象の API を呼び出す定期実行サービス | 決まった時刻に処理を呼び出す仕組み | EventBridge のルールより対象が広く上限も高い |
| S3 | ファイルを名前で出し入れする、容量無制限のストレージサービス | ファイルを置いて名前で取り出す保管場所 | ディレクトリは無い。キーの区切りで表現する |
| バケット | S3 でファイルを保管する、名前が全世界で一意の単位 | S3 の中のファイル置き場の単位 | 名前は後から変えられない |
| RDS | バックアップやパッチ適用を AWS が受け持つマネージドのデータベース | 運用を AWS に任せられるデータベース | この環境では MySQL を使う |
| マルチ AZ 配置 | 別の AZ に待機系を置き、障害時に自動で切り替える構成 | 別の場所に予備を置いて、壊れたら自動で切り替える構成 | 読み取り性能は上がらない |
| リードレプリカ | 参照専用の複製を作り、読み取りの負荷を分散させる構成 | 読み取り専用のコピーを作って負荷を分ける構成 | 反映に遅れがある。直後の読み取りに注意 |
| IAM ユーザー | 人やプログラムに固定の認証情報を持たせる AWS の利用者 | 固定のパスワードや鍵を持つ利用者 | 長期の鍵は避け、ロールを使う |
| IAM ロール | 一時的な権限を引き受けさせるための、認証情報を持たない AWS の識別子 | 必要なときだけ借りる権限のまとまり | 借りる操作は AssumeRole。相手は信頼ポリシーで決まる |
| IAM ポリシー | どの操作をどのリソースに許可・拒否するかを書いた JSON の定義 | 何をしてよいかを書いた許可の一覧 | 明示的な拒否が常に優先する |
| 信頼ポリシー（信頼関係） | そのロールを引き受けられる相手を定めた JSON の定義 | その権限を誰に貸すかを決めた設定 | 権限本体とは別物。両方見ないと原因がわからない |
| Parameter Store | 設定値を名前の階層で保存し、アプリから取り出せる Systems Manager の機能 | 設定値を名前を付けて保管しておく場所 | この環境ではサービスの接続先を共有する用途で使う |
| Secrets Manager | 認証情報を暗号化保存し、定期的な自動入れ替えまで行うサービス | パスワードを預け、定期的に自動で入れ替える仕組み | Parameter Store より単価が高い |
| CloudWatch メトリクス | CPU 使用率やリクエスト数など、時系列の数値を集めて保存する機能 | 時間ごとの数値を集めて記録する仕組み | 標準の粒度は 5 分。細かくすると課金が増える |
| CloudWatch Logs | アプリや AWS サービスが出力したログを集めて保存・検索する機能 | ログを集めて後から検索できるようにする場所 | 保持期間を設定しないと無期限で課金が続く |
| ロググループ | ログを用途ごとにまとめ、保持期間や権限を設定する単位 | 同じ用途のログをまとめた保存先 | 名前は後から変えられない |
| ECR | コンテナイメージを保管する AWS のレジストリサービス | コンテナのイメージを置いておく保管場所 | 古いイメージは保持ポリシーで自動削除する |

## ネットワーク

| 用語 | 意味 | ユーザーへの言い方 | 注意 |
|---|---|---|---|
| 名前解決 | ドメイン名から通信先の IP アドレスを引き当てる処理 | 名前から実際の通信先の番号を調べること | 「DNS を引く」と同義 |
| 権威 DNS サーバー | そのドメインの正しい答えを持ち、問い合わせに回答するサーバー | そのドメインの正解を持っているサーバー | Route 53 のホストゾーンがこれにあたる |
| リゾルバ | 利用者の代わりに DNS を順に問い合わせ、答えを返すサーバー | 利用者の代わりに名前を調べて答えるサーバー | 結果を TTL の間だけ手元に残す |
| A レコード | ドメイン名に IPv4 アドレスを対応づける DNS のレコード | 名前を IP アドレスに結びつける設定 | IPv6 は AAAA レコード |
| CNAME レコード | ドメイン名を別のドメイン名の別名として定義する DNS のレコード | ある名前を別の名前の言い換えとして定義する設定 | ドメインの頂点には置けない |
| ALIAS レコード | AWS のリソースを指し、頂点のドメインにも置ける Route 53 独自のレコード | AWS の宛先を直接指せる、Route 53 専用の設定 | Route 53 でしか使えない |
| TTL（Time To Live） | そのレコードをリゾルバが再問い合わせなしに使ってよい最大の秒数 | 調べた結果を何秒まで使い回してよいかの指定 | 切り替えの前に短くしておく |
| DNS の伝播 | 各リゾルバの古い記録が TTL 切れで入れ替わり、新しい値に揃うまでの経過 | 変更が全員に行き渡るまでの待ち時間 | 実際は伝わるのでなく、期限切れで入れ替わる |
| TLS 終端 | 暗号化された通信をここで復号し、以降を平文で扱う地点 | 暗号を解く場所 | ALB で解くと、その先の通信は暗号化されない |
| 証明書 | そのドメインの正当な持ち主であることを第三者が保証する電子的な証明 | このドメインは本物だと保証する電子的な証明書 | 期限切れで全ユーザーが接続できなくなる |
| リバースプロキシ | 利用者からの通信を受け、裏側のサーバへ中継して応答を返す仕組み | 表で受け取って、裏のサーバへ取り次ぐ仕組み | ALB や Nginx がこの役割を担う |
| CDN | 世界各地の拠点に内容を複製し、利用者に近い拠点から配信する仕組み | 利用者に近い場所から配信して速くする仕組み | 更新が即時に反映されない点に注意 |
| キャッシュ | 一度取得した内容を手元に保存し、次回はそれを返す仕組み | 一度取ったものを取っておいて、次はそれを返す仕組み | 古い内容が残る前提で設計する |
| キャッシュの無効化（invalidation） | 保存済みのキャッシュを明示的に破棄し、次回に取り直させる操作 | 保存した内容を捨てて、取り直させる操作 | CloudFront は回数に応じて課金される |
| パブリックサブネット | インターネットゲートウェイへの経路を持ち、外部と直接通信できるサブネット | インターネットと直接やり取りできる区画 | ここに DB を置かない |
| プライベートサブネット | インターネットへの直接の経路を持たないサブネット | 外から直接は届かない区画 | DB やアプリの本体はここに置く |
| インターネットゲートウェイ | VPC をインターネットに接続するための出入口 | VPC とインターネットをつなぐ出入口 | 1 つの VPC に 1 つだけ付けられる |
| NAT ゲートウェイ | プライベートサブネットから外部への通信だけを可能にする変換サービス | 中から外へは出られるが、外からは入れない通し口 | 常時課金と通信量課金がかかる |
| VPC エンドポイント | VPC から AWS サービスへ、インターネットを経由せず接続する経路 | インターネットを通らずに AWS サービスへつなぐ経路 | NAT の通信料を減らす目的でも使う |
| CIDR | `10.0.0.0/16` のように IP アドレスの範囲を表す記法 | アドレスの範囲を表す書き方 | 数字が小さいほど範囲が広い |

## コンテナと実行環境

| 用語 | 意味 | ユーザーへの言い方 | 注意 |
|---|---|---|---|
| コンテナイメージ | アプリと依存関係をまとめ、どこでも同じように動かせる読み取り専用のパッケージ | アプリ一式を固めた、動かすためのファイル | 「イメージ」だけだと画像と紛れる |
| コンテナ | イメージをもとに起動した、隔離されたプロセスの実行単位 | イメージを実際に動かした 1 つの実行 | 停止すると中の変更は消える |
| レジストリ | コンテナイメージを保管し、配布するサーバ | イメージを置いて配る場所 | AWS では ECR がこれにあたる |
| タグ | イメージに付ける `v1.2.0` のような人が読める目印 | イメージに付ける、人が読める目印 | 同じ目印を別のイメージへ付け替えられる |
| ダイジェスト | イメージの中身から計算した、内容が変われば必ず変わる識別子 | 中身から計算した、絶対にずれない識別子 | 本番はこれで固定すると取り違えが起きない |
| イミュータブルタグ | 一度使ったタグの貼り替えをレジストリ側で禁止する設定 | 同じ目印を別のイメージへ付け替えられなくする設定 | ECR ではリポジトリ単位で設定する |
| オーケストレーション | 多数のコンテナの配置・起動・入れ替え・障害復旧を自動で行う仕組み | たくさんのコンテナを自動で配って動かし続ける仕組み | ECS や Kubernetes が担う |
| ヘルスチェック | 一定間隔で応答を確認し、正常か異常かを判定する仕組み | 生きているかを定期的に確認すること | 判定が厳しすぎると正常なものが落とされる |
| オートスケーリング | 負荷の指標に応じて起動する数を自動で増減させる仕組み | 混み具合に応じて自動で台数を増やし減らす仕組み | 増やす条件より減らす条件を慎重に決める |
| 希望タスク数（desired count） | ECS サービスが常に維持しようとするタスクの数 | 常にこの数だけ動かしてほしいという設定 | 手で止めても自動で戻る |
| コールドスタート | 実行環境の準備から始まるため、応答までに余分な時間がかかる呼び出し | しばらく使っていない状態から起動するときの待ち時間 | Lambda 特有。呼び出しの 1% 未満で起きる |
| 同時実行数（concurrency） | 同じ時点で並行して処理されている実行の数 | 同じ時間に何個並行で動いているかの数 | Lambda はアカウント単位の上限がある |
| グレースフルシャットダウン | 停止の合図を受けてから、処理中のリクエストを終えてプロセスを終了させる動作 | 途中の処理を終わらせてから止まる動き | 実装しないとデプロイ時にエラーが出る |

## デプロイとリリース

| 用語 | 意味 | ユーザーへの言い方 | 注意 |
|---|---|---|---|
| デプロイ | 作成した成果物を実行環境へ配置し、動く状態にする作業 | 作ったものを本番に置いて動かすこと | 利用者に見せることはリリースと呼び分ける |
| リリース | 配置済みの新しい動作を利用者に届け、使える状態にすること | 利用者が新しい機能を使えるようにすること | デプロイと同時とは限らない |
| Blue/Green デプロイ | 新旧 2 系統を並べて用意し、宛先の切り替えで新版へ移す配置方式 | 新しい版を別に用意して、まとめて切り替える | 一瞬で戻せる代わりに、一時的に台数が倍になる |
| カナリアリリース | ごく一部の利用者にだけ新版を流し、問題がなければ対象を広げる方式 | まず少数にだけ新しい版を出して様子を見る | Blue/Green（一括切り替え）と混同しない |
| ローリング更新 | 稼働中の台を少しずつ新版に入れ替えていく更新方式 | 動かしたまま少しずつ入れ替えていく更新 | 新旧が同時に動く時間がある |
| ロールバック | 直前の版へ戻して、問題が起きる前の状態に復旧させる操作 | 前の版に戻すこと | 日本語では「切り戻し」と呼ぶ。どちらか一方に統一する |
| データベースマイグレーション | テーブル定義やデータをアプリの新版に合わせて変更する作業 | データの保存形式を新しい版に合わせて作り変えること | 戻せない変更が多い。実行前に必ずバックアップを取る |
| 後方互換 | 新版が、古い版の呼び出し方やデータ形式をそのまま受け付ける性質 | 新しい版でも、古い使い方がそのまま通る性質 | 新旧が同時に動く更新方式では必須になる |
| ダウンタイム | 利用者がサービスを使えない時間 | 使えなくなっている時間 | 秒単位で見積もって事前に伝える |
| メンテナンス時間帯 | 停止を伴う作業を行うと事前に告知した時間の範囲 | 止めて作業すると事前に知らせておく時間 | 「メンテナンスウィンドウ」と混在させない |
| フィーチャーフラグ | コードを配置したまま、設定で機能の有効と無効を切り替える仕組み | 配置は済ませておき、あとで機能をオンにする仕組み | 使い終わったら消す。残ると分岐が増える |

## 可観測性と運用

| 用語 | 意味 | ユーザーへの言い方 | 注意 |
|---|---|---|---|
| 監視（monitoring） | あらかじめ決めた指標を継続的に測り、異常を検知する活動 | 決めておいた数値を見張って、異常に気づくこと | 「何を見るか」を先に決める点が可観測性と違う |
| 可観測性（observability） | 内部を知らなくても、外に出ている情報から挙動を問い直せる性質 | 外から出ている情報だけで、中で何が起きたか追える状態 | 「オブザーバビリティ」と表記を混ぜない |
| メトリクス | 一定期間ごとに集計された、数値としての測定値 | 時間ごとに集計された数値 | 平均だけ見ると遅い利用者を見落とす |
| ログ | いつ何が起きたかを時刻付きで 1 行ずつ記録した文字列 | 起きたことを時刻付きで書き残したもの | 個人情報や認証情報を書かない |
| 構造化ログ | JSON など機械が解析できる形式で項目を持たせたログ | 後から検索しやすい形で書いたログ | 検索する予定の値は必ず項目に分ける |
| トレース | 1 回のリクエストが複数のサービスを渡り歩いた経路の記録 | 1 回の処理がどこをどう通ったかの記録 | どこで時間を使ったか調べるときに使う |
| スパン | トレースを構成する、1 つの処理区間とその所要時間の記録 | 処理 1 区間分の記録 | トレースは複数のスパンでできている |
| アラート | 指標が決めた条件を超えたときに、人へ通知を送る仕組み | 決めた条件を超えたら人に知らせる仕組み | 対応する人が居る通知だけを鳴らす |
| しきい値 | アラートを出すかどうかを分ける、指標の境目の値 | ここを超えたら知らせる、という境目の数値 | 実測の分布を見てから決める |
| SLI（サービスレベル指標） | サービス品質のある側面を定量的に測る、定義済みの測定値 | サービスの良し悪しを測るために決めた数値 | 応答時間や成功率が代表例 |
| SLO（サービスレベル目標） | SLI がどこまで満たされていれば良しとするかを定めた目標値 | この水準を保てていれば良い、と決めた目標 | 社内の目標。破っても賠償は発生しない |
| SLA（サービスレベル合意） | SLO を満たせなかった場合の結果まで定めた、利用者との取り決め | 守れなかったときの補償まで決めた、利用者との約束 | SLO より緩めに設定する |
| エラーバジェット | SLO を守りながら許容できる失敗の総量 | 目標を守ったうえで、失敗してよい残りの量 | 使い切ったら新機能より安定化を優先する |
| 可用性 | 決めた期間のうち、サービスが正常に使えていた割合 | 使える状態だった時間の割合 | 99.9% は月に約 43 分の停止に相当する |
| レイテンシー | リクエストを受けてから応答を返すまでにかかった時間 | 返事が返ってくるまでの時間 | スループット（処理量）と混同しない |
| パーセンタイル（p95 など） | 全体を小さい順に並べたとき、下から何割の位置にあるかを示す値 | 遅いほうから数えて、何番目あたりかを示す値 | 平均より実感に近い。p95 と p99 を見る |
| インシデント | 利用者に影響が出た、または出る恐れのある障害事象 | 利用者に影響する不具合が起きている状態 | 影響の有無で通常のバグと区別する |
| 重大度（severity） | インシデントの影響範囲と緊急度を段階で表した区分 | どれくらい急いで対応すべきかの段階 | 段階の定義を事前に決めておく |
| オンコール | 決められた期間、障害通知を受けて即応する担当を務めること | 順番に決めた担当が、障害連絡をすぐ受ける当番 | 担当の交代時に引き継ぎを残す |
| ポストモーテム | 起きたこと・影響・対処・原因・再発防止策を記録した事後の文書 | 何が起きてどう直したかを残す事後の記録 | 個人を責めない形式で書く |
| 根本原因 | 取り除けばその事象が起きなくなる、一番奥にある要因 | それを直せば二度と起きない、大元の理由 | 1 つに絞ろうとしない。複数あることが多い |
| 手順書（ランブック） | 特定の障害や作業について、実行する手順を順に書いた文書 | このときはこう動く、と書いた手順の文書 | オンコール担当がその場で読める場所に置く |

## セキュリティと権限

| 用語 | 意味 | ユーザーへの言い方 | 注意 |
|---|---|---|---|
| 認証（authentication） | 相手が名乗った本人であることを確かめる処理 | 本人かどうかを確かめること | 認可と読みが似る。「本人確認」と添える |
| 認可（authorization） | 確認済みの相手に、その操作を許すかどうかを判定する処理 | その操作をしてよいかを判断すること | 認証の後に来る。順番を取り違えない |
| 最小権限 | 業務に必要な操作だけを許し、それ以外は許さない権限の与え方 | 仕事に必要な分だけ権限を渡す考え方 | 迷ったら狭く与え、足りなければ足す |
| 権限昇格 | 本来持たない、より強い権限を得てしまう状態 | 渡していないはずの強い権限を取れてしまう状態 | IAM ロールを作る権限は実質すべての権限になる |
| シークレット | 漏れると被害が出る、パスワードや API キーなどの機密な値 | 漏れると困るパスワードや鍵のこと | コードや Terraform の変数に直書きしない |
| ハードコード | 設定に分離せず、値をソースコード内へ直接書き込むこと | 値をコードの中に直接書いてしまうこと | シークレットは Git 履歴から消しにくい |
| ローテーション | 鍵やパスワードを定期的に新しい値へ入れ替える運用 | 鍵やパスワードを定期的に新しくすること | 旧値の停止まで含めて 1 セットで計画する |
| 一時認証情報 | 有効期限が設定され、期限が切れると使えなくなる認証情報 | 期限が来たら使えなくなる鍵 | 固定の鍵より安全。ロール利用時に発行される |
| OIDC 連携 | GitHub Actions などの外部に、固定の鍵なしで AWS の権限を渡す連携方式 | 固定の鍵を置かずに AWS の権限を渡す仕組み | CI に AWS の固定鍵を置く運用を置き換えられる |
| 多要素認証（MFA） | パスワードに加え、別の手段でも本人確認を行う方式 | パスワードに加えて、もう 1 つ本人確認を足す方式 | 「2 段階認証」と呼び方を混ぜない |
| 署名付き URL | 期限付きの権限を URL 自体に埋め込み、その URL だけで操作を許す方式 | 期限付きで、その URL を知っている人だけが使えるリンク | AWS 日本語表記は「署名付き URL」 |
| 保管時の暗号化 | 保存されたデータを暗号化し、媒体を直接読まれても中身を守る対策 | 保存してあるデータを暗号化しておくこと | S3 と RDS では既定で有効にする |
| 転送時の暗号化 | 通信経路上のデータを暗号化し、途中で読まれないようにする対策 | やり取り中のデータを暗号化すること | TLS を使う。内部通信でも省略しない |
| KMS | 暗号化の鍵を保管し、利用を権限と監査ログで制御する AWS のサービス | 暗号化の鍵を預けて、使用も記録できるサービス | 鍵の削除には待機期間がある |
| 監査ログ | 誰がいつ何をしたかを、後から追跡できる形で残した記録 | 誰が何をしたかを後から追える記録 | 消せない場所に保存する |
| 脆弱性スキャン | イメージや依存ライブラリを検査し、既知の弱点を見つける仕組み | 既知の弱点が混ざっていないか自動で調べること | 検出されても影響の有無を確認してから直す |
| 公開範囲 | そのリソースへ、どこからの通信や誰のアクセスを許すかの設定 | 誰がどこから触れてよいかの設定 | S3 バケットとセキュリティグループで事故が多い |
