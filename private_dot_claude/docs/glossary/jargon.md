# 内輪語 → 標準語の対応表

Claude がセッション内で作った比喩と、その置き換え先を並べる。

`hooks/check-jargon.py` がこの表の「検出パターン」列を読む。そして、応答に内輪語が混ざって
いないか点検する。

収録の根拠は過去セッション 2,410 ファイルの実測値。出現回数は 2026-09-11 時点。

## 表の読み方

| 列 | 中身 |
|---|---|
| 内輪語 | 使ってはいけない語 |
| 検出パターン | hook が使う正規表現。`—` なら機械検出せず、辞書としてだけ使う |
| 標準語 | 代わりに使う語 |
| 補足 | 誤検知の除外条件、使い分け |

検出パターンに `|` は書けない。表の区切り文字と同じ記号だからである。
複数の書き方をまとめたいときは、行を分けて 1 行に 1 つずつ書く。

## 判断に迷ったときの目安

- その語を初めて聞く人が、前後の文だけで意味を取れるか
- 一般語に見えるのに、この会話だけの特殊な意味を持たせていないか
- 数を数える単位（枠 / 班 / 波 / 段）を自分で発明していないか

## 検出しない語（あえて残す）

次の語はユーザー自身が使っているか、日本の開発現場で定着している。検出も言い換えもしない。

| 語 | 理由 |
|---|---|
| 起票 | Issue を作る意味で定着している |
| 棚卸し | 全件の見直しの意味で定着している |
| 正本 | 正式な出どころを指す語としてユーザーの設定文書で使われている |
| 研磨 | `CLAUDE.md` で「表現を研磨する」として定義済み |
| worktree | git の正式な機能名 |

## 育て方

ユーザーが「その言葉がわからない」と言ったら、次の 3 つを行う。

1. その場で標準語に言い換えて答え直す
2. この表に 1 行足す。検出パターンは誤検知しない形にする（一般語と衝突するなら `—`）
3. 置き換え先の標準語が用語集に無ければ、該当分野のファイルにも足す

追記先は chezmoi のソース（`~/.local/share/chezmoi/private_dot_claude/docs/glossary/`）。
追記したら `chezmoi apply` を実行する。
