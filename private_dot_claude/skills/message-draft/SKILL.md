# Message Draft Skill

ユーザー名義のチャットメッセージを、蓄積した文体規範と事例に基づいてドラフト・変換・添削する。

## データ配置（二層構造）

| 層 | パス | 管理 | 内容 |
|---|---|---|---|
| 規範（正本） | `references/style-guide.md` | dotfiles（public） | 一般化された文体規範。固有名詞・社内情報を含めない |
| 事例 | `~/work/workspace/message-drafts/examples/` | ローカル（非公開） | 実メッセージの Before/After と抽出規範 |

## ドラフト手順

1. `references/style-guide.md`（文体規範）を読む
2. `~/work/workspace/message-drafts/examples/` が存在すれば、直近または類似の事例を 2〜3 件読む。**全件は読まない**。ディレクトリが存在しないマシンでは style-guide のみで進める
3. 宛先の種別（他部署 / 社外 / チーム内）を確認し、規範に従ってドラフトを生成する
4. 元になる文章がある変換・添削の場合は、変換後に「元の文章から変えたポイント」を数点添えて提示する

## フィードバック手順（ユーザーが最終版を共有したとき）

1. 自分のドラフトと最終版の差分から、文体規範を抽出する
2. 事例を `examples/` に 1 件 1 ファイル（`YYYY-MM-DD-<slug>.md`）で追記する。構成: 元の文章 / ドラフト / 最終版 / 抽出した規範
3. 一般化できる規範は `references/style-guide.md` へ昇格する。**昇格時は匿名化必須**（社名・人名・案件名・実 URL を除去し、一般語に置換する）
4. style-guide.md を変更したら chezmoi ソースへ反映し、dotfiles ワークフローに従ってコミットする

## 棚卸し（発散防止）

- `examples/` が 20 件を超えたら、規範へ昇格済みの古い事例を要点のみに圧縮する
- `style-guide.md` は常に全文を読める分量（目安 150 行以内）を維持する。超えそうなら規範を統合・整理する

## 機密ルール（最重要）

- dotfiles は **public リポジトリ**。本ファイルと style-guide.md に社名・人名・案件名・社内 URL・実メッセージの引用を書かない
- 実メッセージの内容は必ず workspace 側（`examples/`）にのみ置く
