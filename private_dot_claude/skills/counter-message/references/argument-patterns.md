# 相手の矛盾の型と、観点の組み方

`counter-message` の Step 4 の詳細。相手の文面を型に当て、観点 3〜4 つに束ねる。

## 1. 矛盾の型

| 型 | 何が起きているか | 当てる事実 | 観点の見出しの例 |
|---|---|---|---|
| 都合のよい引用 | 合意の一部だけを引き、例外条項（延期・個別調整・相手側の義務）を落とす | 合意の全文。落ちた条項。合意した当人が例外を宣言していないか | 「引用に含まれていない例外条項」 |
| 取り決めを破った側の主張 | 期限・手順を守っていない側が、相手にルールを求める | 取り決めの初出と全文。依頼の初出・追加の時刻。数え直した本来の日付 | 同上に統合することが多い |
| 片方にだけ寄る負担 | 自分は残業・休日・時間外を負わず、相手には求める | 取り決めの構造（相手の確認で修正が出れば自分側の時間外が確定する等） | 「負担とリスクの配分」 |
| リスクの転嫁 | 自分で決めた日付・約束のリスクを、相手の対応時間の問題にする | 約束は誰がしたか。自分側が約束した事実の有無。取り決めで数えた本来の日付 | 同上 |
| 自分で決めたことを相手の責任にする | 公開日・当日必須の指定・確認体制の有無は相手側が自分で設定した | その選択が相手側で決められたことだったか | 同上 |
| 順序の逆転 | 相手の歩み寄り（時間外の対応の申し出）に不満を返す | 歩み寄りの時刻と内容。取り決めどおりならどうなっていたか | 「担当者の予定と事前の相談」 |
| 原則の外に置いた案件に原則を当てる | 例外を明記した案件に、原則の一部だけを適用する | 例外を宣言した投稿 | 都合のよい引用に統合 |
| 事前の相談なしの日時指定 | 担当者の予定を押さえず、当日に対応を求める | 日時が示された時刻。自分側がその工程に同意したか | 「担当者の予定と事前の相談」 |

## 2. 観点の組み方

- 観点は 3〜4 つ。5 つ以上なら統合する。重複する観点（「まず自分たちが守る」など）は、他の観点に事実を吸収して削る
- 見出しは確認できる事実を名詞句で短く表す（例: 「引用に含まれていない例外条項」）。相手の姿勢や人格を断定する語は見出しに使わない
- 各観点の下に事実を「・」で 2〜4 行。1 行目に最も強い事実
- 自分側が取り決めを満たした事実を 1 つの観点に必ず入れる。締めは「確認できた範囲では、自分側が満たしていない条項はありません」のように、調査の範囲を添える
- 着地は関係性の定義。「対等な協働関係である」→「だからこそ歩み寄っている」→「その関係なら依頼は一方的な指示ではなく相談としてやり取りされるべき」

## 3. 使わない論拠

| 使わない | 理由 | 代わりに |
|---|---|---|
| 少人数・他案件・テスト期間の無さ | 「ならば約束するな」と返される | 「担当者にも予定がある」の根拠として 1 句だけ |
| 1 回目の差分は不備ではない、の弁明 | 守りに見える | 「作り直しなので差分が出る前提で確認工程がある。『修正は発生しない』は相手側だけの想定」と構造で書く |
| 相手の動機（上長への配慮など） | 推測であり、書けば感情論になる | 「期日を守るなら守れる日付で約束すべき」の論理で同じ点を示す |
| 一般論・他社の運用例 | 今回の争点に効かない | 本文に入れない。Artifact の参考に留める |
| 逐条の反論 | 法的に証拠を突きつける印象になる | 観点に束ねる |

## 4. 強さの判定

ユーザーの主張を、送る前に 強い / 弱い で仕分けて伝える。

- 強い: 合意の全文に書いてある帰結（延期条項）、自分側がすでに申し出た事実、相手が自分で決めたこと
- 弱い: 自分側も受けている事実がある主張（「ルール違反だ」）、合意したルールそのものへの批判、相手の言葉を言い換えた引用

弱い主張は、言い方を変えて強い形にする。「ルール違反」→「相手側が満たしていない条項を、自分側が前倒しで受けた」。
