# 相手の矛盾の型と、観点の組み方

`counter-message` の Step 4 の詳細。相手の文面を型に当て、観点 3〜4 つに束ねる。

## 1. 矛盾の型

| 型 | 何が起きているか | 当てる事実 | 観点の見出しの例 |
|---|---|---|---|
| 都合のよい引用 | 合意の一部だけを引き、例外条項（延期・個別調整・相手側の義務）を落とす | 合意の全文。落ちた条項。合意した当人が例外を宣言していないか | 「都合のよい条項だけでルールを主張している」 |
| 取り決めを破った側の主張 | 期限・手順を守っていない側が、相手にルールを求める | 取り決めの初出と全文。依頼の初出・追加の時刻。数え直した本来の日付 | 同上に統合することが多い |
| 片方にだけ寄る負担 | 自分は残業・休日・時間外を負わず、相手には求める | 取り決めの構造（相手の確認で修正が出れば自側の時間外が確定する等） | 「負担とリスクを一方にだけ寄せる姿勢」 |
| リスクの転嫁 | 自分で決めた日付・約束のリスクを、相手の対応時間の問題にする | 約束は誰がしたか。自側が約束した事実の有無。取り決めで数えた本来の日付 | 同上 |
| 自分で決めたことを相手の責任にする | 金曜公開・当日必須・体制なしは自分で選んだ | その選択が相手側で決められたことだったか | 同上 |
| 順序の逆転 | 相手の歩み寄り（時間外の対応の申し出）に不満を返す | 歩み寄りの時刻と内容。取り決めどおりならどうなっていたか | 「担当者にも予定がある」 |
| 原則の外に置いた案件に原則を当てる | 「大きな案件は個別相談」と自分で言っておいて、原則の 2 行だけ適用する | 例外を宣言した投稿 | 都合のよい引用に統合 |
| 事前の相談なしの日時指定 | 担当者の予定を押さえず、当日に「早急に」 | 日時が示された時刻。自側がその工程に同意したか | 「担当者にも予定がある」 |

## 2. 観点の組み方

- 観点は 3〜4 つ。5 つ以上なら統合する。重複する観点（「まず自分たちが守る」など）は、他の観点に事実を吸収して削る
- 見出しは相手の姿勢を名詞句で言い切る（「〜している」「〜姿勢」）。人格の語（「姿勢がおかしい」）は見出しに使わない
- 各観点の下に事実を「・」で 2〜4 行。1 行目に最も強い事実
- 自側が条項を満たした事実（時刻・所要時間）を 1 つの観点に必ず入れる。「〜を満たしていない条項は、自側にはありません」で締められる
- 着地は関係性の定義。「受託先でも部下でも傘下でもない。同じ目線で育てる仲間」→「だからこそ歩み寄っている」→「その関係なら依頼は指示ではなく相談でやり取りされるべき」

## 3. 使わない論拠

| 使わない | 理由 | 代わりに |
|---|---|---|
| 少人数・他案件・テスト期間の無さ | 「ならば約束するな」と返される | 「担当者にも予定がある」の根拠として 1 句だけ |
| 1 回目の差分は不備ではない、の弁明 | 守りに見える | 「作り直しなので差分が出る前提で確認工程がある。『修正は発生しない』は相手側だけの想定」と構造で書く |
| 相手の動機（上長への配慮など） | 推測であり、書けば感情論になる | 「期日を守るなら守れる日付で約束すべき」の論理で同じ点を突く |
| 一般論・他社の運用例 | 今回の争点に効かない | 本文に入れない。Artifact の参考に留める |
| 逐条の反論 | 法的に証拠を突きつける印象になる | 観点に束ねる |

## 4. 強さの判定

ユーザーの主張を、送る前に 強い / 弱い で仕分けて伝える。

- 強い: 合意の全文に書いてある帰結（延期条項）、自側がすでに申し出た事実、相手が自分で決めたこと
- 弱い: 自側も受けている事実がある主張（「ルール違反だ」）、合意したルールそのものへの批判、相手の言葉を言い換えた引用

弱い主張は、言い方を変えて強い形にする。「ルール違反」→「相手側が満たしていない条項を、自側が前倒しで受けた」。
