# 反論文の型とセルフチェック

`counter-message` の Step 6〜7 の詳細。`message-draft` の文体規範（構成・言い回し・枕詞）を前提に、反論文で上書きする点だけを書く。固有名詞・実メッセージは書かない（事例は workspace 側）。

## 1. 構成

```
<枕詞。初対面なら「はじめまして」> お疲れ様です。
<部署 役職 の 名前> です。

<いつの何について返すか。送り先を変えた理由は書かなくてよい>
<決着済みの事柄があれば切り分け: 「本件の進め方ではなく、ご投稿の内容とその前提になっている考え方についてです」>

率直に申し上げて、<承服しかねます / 納得していません>。

■ 1. <観点: 相手の姿勢を名詞句で>
・<最も強い事実>
・<事実>
・<事実>

■ 2. <観点>
・…

■ 3. <観点>
・…

■ お願い
・<マナーとして求めること 1>
・<マナーとして求めること 2>

■ 最後に
<関係性の定義>。<だからこそ歩み寄っている事実>。<その関係なら、依頼は指示ではなく相談でやり取りされるべき>。<上のお願いはその関係を保つためのもの>。

よろしくお願いいたします。
```

## 2. 型の規則

- **逐条でなく観点で組む。** 相手の文を 1 文ずつ引用して事実を当てる形は「証拠を突きつける」印象になる。観点 3〜4 つに束ね、各観点の下に事実を「・」で置く
- **冒頭で決着済みの件を切り分ける。** 進め方の交渉ではなく、相手の文面の考え方への返答だと明示する
- **立場は最初に言い切る。** 「率直に申し上げて、承服しかねます」。感情の語（遺憾・不快・心外）は使わない。「理由を N 点に」の前置きは要らない（見出しの番号で分かる）
- **着地は関係性の定義。** 「受託先でも部下でも傘下でもない。同じ目線で育てる仲間」。だからこそ歩み寄っている、の順
- **お願いは運用の条件にしない。** 「〜の場合は翌営業日」のようなルール調は指示に見え、着地と矛盾する。マナーとして求めることを 2 点前後に絞る。打ち合わせの提案は、ユーザーの指示がなければ入れない
- **相手に求める姿勢は「認識してほしい」の水準。** 禁止ではなく「〜があって成り立っていることを前提に」
- **双方向の言い方にする。** 「いただきたいです」より「〜されるべきだと考えます」。対等な関係なら求めるものは双方に掛かる
- **自側が条項を満たした事実を時刻で書く。** 「17:00 の条項は 14:31 に終え、その後の修正 2 回にもそれぞれ 2 時間余りと 1 時間以内で対応」のように所要時間まで
- **相手の言葉は実際の文言で引用する。** 言い換えた引用（「死守」など相手が使っていない語）は使わない
- **読み手の視点で語を選ぶ。** 相手が別の意味で使う語（例: 「事業部」）を自側の意味で使わない。「関係先」のように視点に依らない語にする
- **送信が日付をまたぐなら「本日」を日付に置換する。** 予約投稿では特に。相手の言葉の引用の中の「本日」はそのまま
- **自側の余裕の無さを根拠にしない。** 少人数・他案件・テスト期間の無さは「予定がある」の根拠として 1 句だけ
- **相手の動機を書かない。** 構造で突く
- **1 回目の差分は不備と書かない。** 作り直しなら差分が出るのは前提で、確認工程はそのために置いてある。「修正は発生しない」は相手側だけの想定

## 3. セルフチェック表

送る前に全部当てる。

| # | 点検 | 直し方 |
|---|---|---|
| 1 | 「理由を N 点」と節の数が合っているか。節を削ったら数も直す | 数を直すか、前置きを消す |
| 2 | 「本日」「明日」が送信日とずれないか | 日付に置換 |
| 3 | 相手の部署・自側の部署・第三者の呼び方が、読み手の視点で一貫しているか | 「関係先」など視点に依らない語に |
| 4 | 相手の引用は実際の文言か | 原文に合わせる |
| 5 | 感情の語・人格の語（姿勢がおかしい・無責任）が無いか | 構造の語に |
| 6 | 自側の弱みの候補を、ユーザーに確かめずに「弱み」と書いていないか | 確かめる。論点の入口に置き直す |
| 7 | お願いが運用の条件や打ち合わせの提案になっていないか | マナーの水準に |
| 8 | 「指示ではなく相談」の一文が本文のどこかにあるか（お願いを削ったときに消えやすい） | 「最後に」に戻す |
| 9 | 文末の句点の有無が箇条書きで揃っているか。「下さい」→「ください」 | 揃える |
| 10 | 自側が条項を満たした事実が時刻付きで入っているか | 時系列から足す |

## 4. 進め方の規則

- 文案の全文は Artifact の要点の直下に置く。ユーザーは節ごとに指摘して直す。全文を 1 回の質問で確定しようとしない
- お願いの候補は `multiSelect` で出し、選ばれたものだけ書く。推奨を付けるのはよいが、勝手に入れない
- ユーザーが「弱い」と言ったら事実を増やさず観点の切り方を変える。「法的・証拠を突きつける感じ」と言ったら逐条をやめる
- 最終版を受け取ったら事例を保存し、一般化できる規範をこのファイルへ匿名化して昇格する
