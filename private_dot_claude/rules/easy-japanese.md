# やさしい日本語

Claude が日本語で書く全テキスト（チャット / Issue / PR / コメント / 計画）に適用する文の組み立て方。出典は hellouniweb の「やさしい日本語」をネイティブ向けに絞ったもので、運用で加えた R7〜R9 を足している。技術用語のカタカナ語（デプロイ / リファクタリング / コミットなど）とコード識別子は対象外。言い換え例の一覧は `docs/easy-japanese-examples.md`。

| # | 規律 | 要点 |
|---|---|---|
| R1 | 一文を短く | 主語と述語が 1 対 1 の単文を基本にする。理由や条件は別の文に切る |
| R2 | 主語と動作主を明示 | 能動態で書く。「それ」「これ」が指す対象を直前に置く |
| R3 | 3 つ以上は箇条書き | 手順・条件・選択肢を句読点で並べない |
| R4 | 一般語の外来語は日本語に | エビデンス → 証跡、アサイン → 割り当て。技術用語は変えない |
| R5 | 二重否定を使わない | 「対応していないことはない」→「対応している」 |
| R6 | 期限・数量は具体値で | 「後日」「いくつか」ではなく日時・数・範囲で書く |
| R7 | 名詞句の連結より動詞句 | 「PdM ヒアリング」→「PdM にヒアリングする」。誰が何をどうするかを開く |
| R8 | project 固有名詞は役割を併記 | 初出のファイル名・テーブル名・文書名に役割を添える。例: `target-persona.md`（ターゲット属性） |
| R9 | 総称語より対象物の用語 | 対象が 1 つに決まる場面で leaf / caller / node と書かない。「ECS クラスタ定義」のように対象物で書く。標準語は `terminology.md` と `docs/glossary/` を引く |

## R7〜R9 の対象外

- R7: 技術用語のカタカナ語、慣用句として固まった名詞句（定期実行・全体調整）、表のセルや見出し
- R8: 一般語（API / DB）、技術用語（React / Slack）、project のユビキタス言語、末尾 `/` のディレクトリ名、構造用語と組み合わさる固有名（Figma の `Design_マイページ`）。同じ本文内の 2 回目以降は名称だけでよい。迷ったら併記する
- R9: その製品が定義する正式名称（Kubernetes の Node、Terraform の resource ブロック）、コード識別子、見出し、規律を説明するために語そのものを挙げる場合

## 読み返すときの点検

- 一文に論点が 2 つ以上入っていないか（R1）
- 「誰が」が落ちていないか（R2）
- 3 つ以上の並列を句読点で並べていないか（R3）
- 期限・数量があいまいなままか（R6）
- 動作名詞（ヒアリング / レビュー / 把握 / 整備 / 共有 / 確認 / 反映）を名詞のまま連結していないか（R7）
- 初出の固有名詞に役割を添えたか（R8）
- 対象が決まる場面で総称語を使っていないか（R9）
