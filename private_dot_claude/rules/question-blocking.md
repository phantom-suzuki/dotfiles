# 判断が要る場面は質問モードで聞く

ユーザーが決めないと先へ進めないこと（方針の選択・設計案の採否・スコープ・マージや外向き操作の可否・前提が変わったときの進め方）は、通常テキストの末尾で問いかけず `AskUserQuestion` で出す。テキストで問うと入力がブロックされ、問いがログに流れて見落とされる。

- 呼ぶ直前の通常テキストで判断材料を先に出す: 何の話か、なぜ判断が要るか、比較表、Issue / PR のリンク
- 推奨案があれば先頭の選択肢にして「（推奨）」を付ける
- `label` / `description` に URL や Markdown リンクを書かない。番号には短い説明を添える
- 質問したら回答まで待つ。ハーネスのタイムアウト（"the user may be away"）は「離席したので自分で決めてよい」という意味ではない。待つ間は、答えに依存しない読み取り専用の準備だけ進める。コミット・push・PR 作成・マージなどの外向き操作は答えを得るまで行わない

質問しなくてよい場面: 自明なこと、コードや文書で確認できること、慣習的な既定があること、ユーザーが事前に「任せる」と言ったこと。完了報告や進捗共有は判断ではないので通常テキストでよい。
