# 用語の選び方

ユーザー向けの文章で使う語の決まり。日本語の組み立て方は `easy-japanese.md` に書いてある。
用語集の本体は `docs/glossary/` にある。常時読み込まないので、迷ったときに自分で開く。

- 業界標準の用語を主役にする。IT の標準用語はカタカナや英語のまま書く（ミラー / スキップ / デプロイ / バナー / User-Agent）
- 標準用語を和語に置き換えない。「写し」「飛ばし」「配信（デプロイの意味）」「帯」「絵」は読み手に通じない
- 標準語が思い出せないときは和語を造らず、英語のまま書いて `docs/glossary/` を引く
- 聞き慣れない用語は初出で 1 句の説明を添える。説明で置き換えるのではなく、用語と説明を並べる
- 日本語の比喩を発明しない。数える単位（枠 / 班 / 波 / 段）も発明しない
- 対象が 1 つに決まる場面で総称語を使わない。対象物の名前で書く

## 頻出の言い換え

| 使わない | 使う |
|---|---|
| 司令塔 / HQ | 統括セッション |
| 枠 / 班 / レーン | 並列セッション / 担当セッション |
| 第 N 波 / 波 N | 第 N 回の実施 |
| 窓 / 窓明け | 作業できる時間帯 / その終了 |
| 第 N 段 / N 段目 | 第 N 工程 |
| 器 / 受け皿 / 束 | 対象物の名前（親要素・まとまり など） |
| leaf | Task Issue / 末端の Issue |
| caller | 環境ごとの設定ディレクトリ |
| 投入 | 何をどこへ取り込むか目的語を書く |
| 検算 | 数え直しての照合 |
| 写し | ミラー / コピー |
| 飛ばす / 飛ばし | スキップ |
| 配信（デプロイの意味） | デプロイ |
| 帯 / 絵 / 札 | バナー・ヘッダー / 画像 / バッジ・ラベル |
| 門 / 守り | マージ前の必須チェック / ガード（チェック） |
| 係 / 経路（処理の意味） | 担当 / 接続・処理（具体名で書く） |
| 置き場 / 合図 / 見張り | ディレクトリ・保存先 / 通知・トリガー / 監視 |
| 道具 / 裁定 | ツール・スクリプト / 決定 |
| 名乗り / 横送りの部品 / 型紙 | User-Agent / カルーセル / スナップショット（比較の基準） |

## 用語集の使い分け

| ファイル | 引く場面 |
|---|---|
| `docs/glossary/jargon.md` | 内輪語の対応表。上の表の正本。`[block]` 付きの行は Stop フックが応答を差し戻す |
| `docs/glossary/design.md` | 設計・アーキテクチャ・実装品質 |
| `docs/glossary/infra.md` | インフラ・クラウド・IaC・運用 |
| `docs/glossary/process.md` | Git・レビュー・テスト・スクラム |
| `docs/glossary/ai-agent-ops.md` | セッション運用・委譲・並列実行 |

## 用語集の育て方

- ユーザーが「その言葉がわからない」と言ったら、標準語に言い換えて答え直す。そのあと `docs/glossary/jargon.md` に 1 行足す（手順は同ファイルの末尾）
- 新しいプロジェクトに入るときは `glossary-research` スキルでその業界の用語を集め、プロジェクトの `docs/glossary/` に置く
- 週 1 回（月曜）、launchd が会話ログから造語の候補を `~/.claude/state/glossary-candidates.md` に書く。`glossary-research` スキルの review で用語集へ反映する
